## Stop before Delete

**Stop and Delete are always separate actions.** Active rows offer View export and Stop, never Delete. An accepted Stop appears as **Stop requested**, stays in Active exports, disables repeat Stop and retains **Check status**. It must not look finished merely because the local run enum says `interrupted`.

For **live exports**, Delete appears only when current export metadata reports `deletionState: ready`, including actual settled native cancellation where required. `stop-required` offers Stop; `settling` keeps Delete unavailable even if the run status is `interrupted`. A stale eligibility decision is refused by the server with `409`; reread metadata without deleting or automatically repeating Stop. A Stop whose outcome is unconfirmed retains the last known state and offers a read-only check, not a success message or automatic resend.

**Approved restored-snapshot exception:** exports restored from backup are inert snapshots. The daemon never reconnects them to the old agent. Reuse the same request/status composition for three states: Restored snapshot with Stop; an inline local-discard acknowledgment with an explicit unchecked “I understand this does not stop old remote work” checkbox and Confirm local discard; then Local discard confirmed with separate Delete. Confirmation sends the existing local Stop command; reread export metadata and expose Delete only after `deletionState: ready`. For a locally terminal, intent-backed restored export, Stop records local discard without changing native cancellation facts or contacting the old provider. This allows deletion of only the restored local record even when old remote status remains unknown. Do not offer remote checking/reconnection or label native cancellation settled. The subsequent Delete dialog repeats that old remote work may still be running and local deletion does not stop it. Live-export settlement rules remain unchanged.

The native Delete confirmation identifies the request, initially focuses Cancel and permits Escape before submission. Pending deletion disables both actions and cannot be cancelled by dismissal. A deletion error retains the item; an unknown outcome is checked against the same identity, never treated as success or recreated automatically. Successful deletion returns to the existing catalog and announces the result.

**Full local deletion is approved.** The user’s final clarification supersedes the earlier diagnostic-retention recommendation: delete the saved report, visible history entry and export-specific internal execution records/report copies. Live exports must be safely terminal and actually settled; restored inert snapshots use the approved local-discard acknowledgment above, without asserting remote settlement. Do not retain export-specific execution evidence as a diagnostic policy. Preserve thoughts, unrelated records and already-downloaded files. As the current API documents, local deletion does not erase provider history, backups or SQLite free pages/WAL. The dialog’s design-note paragraph is review-only and must not ship. ## Capability and recovery boundary

The current [Agentic export contract](../../../docs/daemon-api.md#agentic-export), including [history and local deletion](../../../docs/daemon-api.md#history-and-local-deletion), now supports this composition. `GET /exports/agentic` returns `{items,nextCursor}` with each item’s `id`, `status`, `createdAt`, original `request`, `effort`, `restored` and `deletionState`. It lists retained-intent exports in live descending `(createdAt,id)` order, not a snapshot; legacy runs without intent are excluded. Optional `limit` is 1–200, default 50; continuations use the opaque endpoint/limit-bound cursor, and restart requires a fresh listing.

`GET /exports/agentic/:runId/metadata` supplies the current item and deletion eligibility. `DELETE /exports/agentic/:runId` returns `204` after ready local deletion, `404` when absent/non-export, or `409` when Stop/settlement is required. [Stop](../../../docs/daemon-api.md#stop-post-runsidstop) remains `POST /runs/:id/stop` with `{}`; its unchanged run response does not itself certify deletion readiness. Recheck metadata after live Stop or restored local-discard acknowledgment. Admission and Markdown download retain their existing contracts. All export routes are user-only and private/no-store. Production browser calls must still use the Next.js server boundary, never daemon credentials or direct daemon access. The HTML is illustrative and does not call these routes.

Preserve confirmed rows/report bytes if a later read fails and label the current observation unconfirmed. Loading or an empty list never creates a request. First-read errors offer Check exports. A non-null `nextCursor` exposes More exports; retain earlier rows on continuation failure and offer a fresh listing for an invalid/restarted cursor. New requests and unsent drafts do not gain a cross-reload persistence promise from these comps. Unknown admission does not invent a saved export, run ID or Stop action. Sample status/local-discard transitions are deterministic mock navigation, not a substitute for metadata confirmation or a promise that one check settles cancellation.
