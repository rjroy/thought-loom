## Entry, saved sessions and navigation

Ordinary Explore remains fast keyword search. Its separate **Ask your library** link opens the conversational-search entry; **Saved searches** opens the session catalog/sheet. Neither ordinary Search nor page rendering implicitly invokes an agent. Shared Capture remains available.

**New search** is explicit user intent: create an empty session and blank composer, then expose its canonical session URL; it does not call a model. Do not invent a greeting, findings or a seed conversation. Creation, composer creation and turn admission are writes: **GET, render, navigation prefetch and polling must never perform them.** A bookmarked unopened session can reuse the existing workspace header/status area with an explicit **Resume** action before loading a new composing context; no new landing-screen layout is required. Revalidate an existing known composer rather than silently resetting its coverage.

Sessions persist until user Delete. Resume restores saved conversation/discoveries through eligible reads, not an opaque native chat. Refresh/open is not a new session/turn. Implemented bookmarkable routes are `/explore/ask` (entry), `/explore/ask/saved` (catalog), `/explore/ask/:id` (session) and `/explore/ask/:id/history` (user-only inspection); Idea destinations retain their existing routes. A bookmark does not promise persistent unsent text. Preserve in-document unsent drafts and scroll/place per session when switching or browsing an Idea; no new daemon scroll/draft fields, automatic bottom jumps while reading older content, or local-storage/offline/autosave promises. Use current last activity, not invented message-preview metadata. On a changed/expired catalog cursor, refresh the listing without duplicating selection or writes.

## State and behavior handoff

Only the primary composition and supporting specimens above are selected rasters. The following are **contract-driven states using those layouts and existing labelled field/status/dialog/disclosure patterns**, not claims of additional approved screenshots. [Current daemon API](../../../docs/daemon-api.md#agentic-search-sessions) is authoritative; this handoff adds no endpoint or capability.

| State | Presentation and allowed next action |
| --- | --- |
| Fresh/empty | Empty chronological conversation and discoveries, no fabricated greeting or minimum blank chat height. Label the writing field; Send needs nonempty text and a valid composing context. No-results reply is valid without discoveries. |
| Queued/submitting/running | Honest worded Queued / Searching status, Check and known-run Stop. No streamed reasoning, tool trace, percentage, ETA, progress counts or partial assistant prose. Disable duplicate admission; confirmed discoveries can accumulate independently of the final reply. |
| Known run uncertain | Keep its known identity and last-confirmed records; say the search status is uncertain. Check and Stop address that same run. This is different from unknown admission without a run identity; neither state admits duplicate work. |
| Clarifying | Show the eligible final assistant question. Awaiting-user completes that run; the user's answer is a new explicit turn, not a permanently running job. |
| Completed | Read the actual eligible saved assistant message/discoveries before presenting them as recorded. A final reply does not expire/close the saved session. Control-only success is not conversation text. |
| Failed/stopped | Retain confirmed records and distinguish failure from user Stop. No fabricated final reply or automatic Retry/Resume of the old turn. A deliberate next Send is new intent. Stop fences locally; if cancellation is pending, say remote stopping is not yet confirmed. Leaving the page is neither Stop nor Delete. |
| Admission unknown | “Not sure this request started. Check before sending again.” Retain the original request snapshot as a separately labelled copyable local snapshot, not an optimistic conversation message. No success checkmark, new-key retry or guessed run. Check uses the same request key; a missing receipt is not proof the original cannot arrive. Resolve only control identity/status, then perform fresh eligible content reads. Deliberate reconciliation, if needed, preserves the exact original key/payload. |
| Observation/read failure | Retain last-confirmed status and safe controls, label the observation problem and offer Check/reload of the same read. A network failure does not prove execution failed or authorize another turn. Missing agent configuration before fresh admission says no search started; an unavailable configured service can leave already admitted work queued. |
| Context changed | Block Send; keep old unsent text visible/copyable in a clearly separated draft area. Explain “Context changed. This draft cannot be sent.” Offer **Start a new blank draft** explicitly; never copy/rebase the old draft or silently create a fresh context as recovery. Re-fetch all visible normal content for the new context. |
| Unavailable/rejected dependency | Use worded Message unavailable / Idea unavailable / Explanation unavailable placeholders, according to returned availability. Do not expose unsafe titles, prose, rationale or indirect evidence. Do not infer rejected versus missing from an unavailable response or automatically broaden scope. |
| Delete | Supporting confirmation: “Delete this search?” / “Conversation and discoveries will be removed from Thoughtloom. Library ideas stay.” Cancel first, destructive Delete search second. Pending Delete disables repeat action and retains honest state; uncertain Delete is checked against the same session, not recreated. On confirmed local deletion, leave the session for the existing catalog/empty workspace. Never promise provider/OpenCode/backups erasure or block local success until remote cleanup finishes. |

## Discoveries, preview and history safety

- Append **existing** thought occurrences in confirmed append order; the agent cannot silently remove earlier discoveries. Refresh live membership, not cached add receipts. Remove from search affects that occurrence only, never rejects/deletes the thought or a connection. After confirmed removal, do not let a stale page restore it. A later fresh discovery may add the same thought at the tail; retrying the old removal cannot remove that later occurrence. No pinning, sorting, permanent suppression or invented Undo promise.
- Preview is an eligible, read-only expansion of the discovery's current thought in the same composing context. Register its eligible dependencies through the dedicated preview contract; it is not a model full-read witness. Open idea navigates to the existing Idea view, not an inline Capture/Evolve action. Preserve search return state; returning must revalidate eligibility rather than turn an old preview into trusted context.
- **History** is deliberate user-only inspection using the same chronological/list reading language, a visible **History · User-only** heading, no composer/Send, and a clear return to the session. It may include removed occurrences and historical unavailable material only under the explicit history contract. It is never a normal-read fallback, AI input, rejected-AI toggle or source of a new draft. No unselected alternative's history/error sketch is implicitly approved.

## Consumer boundary and implementation verification

Browser → fixed-purpose Next.js server routes/actions → Hono daemon; credentials stay server-side. Preserve private/no-store and current authentication/Host/Origin protections. The client supplies user intent, request keys and an intent clock/time zone, never daemon record IDs/timestamps, authorship/classification or invented native identity. Canonical IDs returned by the daemon are navigation/reference values, not client-assigned records.

Normal content/preview reads are bound to their composer and its complete offered coverage. History has no composer token. Admission/by-key/Check/Stop DTOs are control-only and cannot render recovered/optimistic message prose. Never reuse a cached/request snapshot from an old context beside a new composer, silently reset a changed context, or create a new blank composer in a render/poll. After any valid context transition, fresh normal reads—not an old draft or DTO—supply displayed conversation. Forward the discovery-removal revision and honor it against stale membership reads. Preserve submitted clock/key/payload during exact reconciliation; a new clock is not permission to reinterpret “yesterday morning.”
