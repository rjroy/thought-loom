# Retained media import backend

## Scope and authority

Proposed backend design for `thought-loom-dkx`, not an implemented contract or implementation authorization. Initial import accepts one local image or PDF. Audio, video, bulk media import, remote fetching, deletion, deduplication and a general attachment platform are outside this proposal. Client implementation and visual design remain separate scopes.

The user has approved retaining original bytes outside SQLite in a private daemon-managed directory, retaining metadata and relationships in SQLite, and backing up both. Optional clarification guides an otherwise source-grounded summary. The original source idea displays the file and clarification; a separate AI-authored child holds the searchable interpretation. PDF extraction must not create additional source-text thoughts. Weaver and Evolve must discover and be able to reopen eligible retained media. Failed interpretation preserves the source and exposes failure, with deliberate retry without reupload. The existing configured-model/trusted-tool policy applies without per-file approval or automatic model switching.

## Required proposed contracts

These choices affect persistence or observable behavior and must survive implementation refactoring. The file layout, dependency seams and suggested resource defaults below are implementation recommendations, not additional product decisions.

### One immutable source submission, then an interpretation

Recommend a narrow new `media-original` root: `author:'source'`, `kind:'media-original'`, `text:null`, `origin:'media-import'`, `parentId:null`, `sourceIds:[]`, initially null title metadata. This identifies the unverified original file, not invented user prose. Store optional exact nonblank clarification on its immutable media-source record, attributed separately to the importing user; absence is null. Default summary instructions belong only to the daemon prompt. Never persist a placeholder sentence as thought text.

Two honest alternatives are a narrow text/media discriminated source union without a new kind, or a dedicated media kind with nullable text only for that kind. The user approved the latter: an explicit kind makes source attribution, validation and export dispatch unambiguous, at the cost of an enum/CHECK migration and consumer updates. Existing text thoughts retain nonempty immutable text; this does not introduce arbitrary optional-text thoughts or a general attachment platform.

The source relationship is exactly one retained file to one new source root. It cannot later attach to another existing thought, replace its bytes, change clarification or acquire additional files. Changed instructions use Evolve; changed bytes require a new import. A successful initial interpretation is one `ai-interpretation` child of that root through the existing weave operation. Additional supporting thought IDs are provenance, never extra parents. Later Evolve developments retain their existing contribution parent rule.

Normal and inspection Thought projections become a discriminated union. Existing kinds keep their fields; a media root has `text:null` and a required scoped `mediaSource:{id,name,mimeType,byteLength,fileAuthorship:'unverified',clarification,clarificationAuthor}`. `clarificationAuthor` is `user` exactly when clarification is present, otherwise null. The title fallback is its display filename, never persisted thought text. All record, relationship, agent and export projections must handle this variant rather than substitute a sentence or empty user thought.

Index only exact clarification (if any) and editable titles for media roots, plus existing AI child/reply text. File names, binary/extracted content and other media metadata stay out of FTS/spelling vocabulary unless deliberately recorded as title metadata. Add `media-original` to kind filters/counts. A media search hit has `text:null`, its descriptor, and a clarification-only snippet (empty if absent). Simple export renders a labeled file/source descriptor, source authorship and separately labeled exact user clarification, not an invented thought body. Agentic citations retain the media kind and distinguish reading its descriptor/clarification from reading the binary. Binary export/backup remains separate. These are required changes to the current [text-only export](../../../src/domain/simple-export.ts#L22) and [title fallback](../../../src/domain/thought.ts#L51), not capabilities already implemented. No extracted PDF text becomes a thought.

### Proposed SQLite additions

All columns are `NOT NULL` unless marked nullable. IDs and request keys are nonempty; daemon media IDs use a canonical opaque UUID spelling. Integers require SQLite integer type and safe nonnegative values, with the stricter bounds below. No source-byte BLOB column is added.

| Table | Exact fields and constraints |
| --- | --- |
| `media_store` | `singleton INTEGER PRIMARY KEY CHECK(singleton=1)`; `store_id TEXT UNIQUE`. One immutable daemon-generated identity shared with the directory marker, not a path or credential. |
| `media_sources` | `id TEXT PRIMARY KEY`; `source_thought_id TEXT UNIQUE REFERENCES thoughts(id) DEFERRABLE INITIALLY DEFERRED`; `request_key TEXT UNIQUE`; `display_name TEXT`; `mime_type TEXT CHECK IN ('image/png','image/jpeg','image/gif','image/webp','application/pdf')`; `byte_length INTEGER CHECK(0<byte_length AND byte_length<=9007199254740991)`; `sha256 BLOB CHECK(typeof(sha256)='blob' AND length(sha256)=32)`; nullable `clarification TEXT`, nonblank when present; `created_at TEXT`. Digest is **not unique**. All fields are immutable; clarification authorship is derived from user-only admission, not file authorship. |
| `media_weave_attempts` | `source_id TEXT REFERENCES media_sources(id)`; `position INTEGER CHECK(position>=0)`; `run_id TEXT UNIQUE REFERENCES runs(id)`; `request_key TEXT`; `open_slot INTEGER DEFAULT 1 CHECK IN (0,1)`; nullable `interpretation_thought_id TEXT UNIQUE REFERENCES thoughts(id)`; nullable `failure_code TEXT`; `cleanup_state TEXT DEFAULT 'none' CHECK IN ('none','pending','settled','ownership-conflict')`; nullable JSON-valid `cleanup_identity_json TEXT` and `retry_evidence_json TEXT`; `PRIMARY KEY(source_id,position)`; `UNIQUE(source_id,request_key)`. Partial unique indexes on `source_id WHERE open_slot=1` and `source_id WHERE interpretation_thought_id IS NOT NULL`. Cleanup identity is present exactly when state is not `none`; retry evidence is present exactly when state is `settled`. |
| `run_media_parts` | `prompt_id TEXT REFERENCES run_steps(prompt_id)`; `position INTEGER CHECK(position>=0)`; `source_id TEXT REFERENCES media_sources(id)`; `representation TEXT CHECK IN ('original','derived')`; `mime_type TEXT`; `byte_length INTEGER CHECK(byte_length>0)`; 32-byte BLOB `sha256`; nullable `prepared_key TEXT UNIQUE`; nullable JSON-valid `recipe_json TEXT`; `observed INTEGER DEFAULT 0 CHECK IN (0,1)`; `PRIMARY KEY(prompt_id,position)`. Original representation requires null key/recipe and exact equality with its immutable source MIME/length/digest. Derived representation requires both key and recipe. |

Required guards:

- Source rows, store identity and media-part identity/payload metadata reject update, deletion and replacement. The only media-part update is `observed:0→1`, with trusted correlated receipt/history evidence. Attempt identity is immutable; its result, failure, cleanup identity and retry evidence are write-once, and `open_slot` only closes. Cleanup state allows only `none→pending→settled|ownership-conflict` under the sealed reconciliation contract below; repeated exact terminal writes are idempotent.
- Insert the source row **before** its new root in one immediate transaction. Reject source insertion when its target thought already exists. A thought-insert trigger requires a matching source row exactly for `kind='media-original'` and validates its null text, source authorship, root/origin fields and equal creation time. The source's deferred FK prevents a source-only commit. Thus existing thoughts cannot gain files later, and a media root cannot commit without its association. Forbid supporting-source insertion on these roots; create their normal empty source seal and null title row in the command transaction.
- Attempt insertion requires an ordinary `weave` run whose subject is this source root and trigger is `media:<source-id>:<position>`. Positions are contiguous from zero. Position zero uses an internal initial key. Later admission requires the retry rules below. Terminal run transitions close the slot in the same transaction. Do not admit a second initial interpretation after a confirmed one, including after its rejection.
- Setting `interpretation_thought_id` requires this run's matching interpretation receipt and issued membership, an AI interpretation with the source root as parent, currently eligible exposed context, and observed media parts covering its declared source representation. Reading only the root's instructions is insufficient. Save the child, receipt, issued membership and pointer atomically. Initial media attempts allow at most one interpretation operation. Before that interpretation exists, permit reads and conditional title fill, but not connection writes, so a failed interpretation cannot leave connections that a retry repeats.
- Every weave targeting a media root is either its admitted interpretation attempt or title-only work, as defined below. Check that persisted purpose before capability dispatch **and replay**, not just in prompts. Parts are inserted only while their owning step is current, queued/prepared and has null input, for a non-title-only Weaver/Evolve run and an AI-eligible source. They have contiguous positions and are sealed by preparation of `run_steps.input`. Include their canonical manifest in that exact input; reject late or mismatched parts. Reading a descriptor/clarification is not reading the binary. Grant media-read evidence only after exact attachment admission/history matching, not on preparation or submission intent.

`failure_code` is a stable sanitized code from the closed set `original-unavailable`, `unsupported-model-input`, `media-transport-incompatible`, `conversion-unavailable`, `invalid-output`, `interpretation-missing`, `processing-failed`, `interrupted`, `context-unavailable`. Cleanup identity and retry evidence use the strict versioned forms below. No raw errors or source content belong in them. SQL JSON validity is not authorization or independent proof of native facts.

This requires a **thought-table/FK-closure migration**, not just additive tables. Widen `kind` with `media-original`; replace `text NOT NULL` with `CHECK((text IS NULL)=(kind='media-original'))`; replace the source-author CHECK with `(author='source')=(kind IN ('imported-original','media-original'))`. Preserve `(kind='imported-original')=(import_document_id IS NOT NULL)` and its Markdown origin/root constraints; require media roots to have null import membership. Domain validation keeps nonempty text for every existing kind and accepts null only for media originals. Add tables/guards through core [`migrate()`](../../../src/storage/sqlite.ts#L39), after existing predecessor migrations, inside its immediate transaction with FKs and recursive triggers enabled. The current [closure rebuild](../../../src/storage/import-migration.ts#L52) rejects cyclic predecessors, so it is not reusable unchanged: current Markdown document/seal cycles require a cycle-aware, staged rebuild preserving incoming FKs, rowids, bytes, indexes and triggers. Do not edit `sqlite_schema`, fabricate source text/backfill associations, or disable integrity checks to evade that work. Rebuild media FTS projections from clarification/title without changing stored legacy text; validate repeat migration, rollback and `foreign_key_check` on isolated current and older fixtures. Run kinds remain unchanged.

### Every weave trigger targeting a media root

The current [title-clear writer](../../../src/storage/title.ts#L33) schedules an ordinary weave using [`titleClearWeaveIntent`](../../../src/domain/weave-scheduling.ts#L13); that weave can currently [issue interpretations](../../../src/storage/run-operations.ts#L44). The proposed guard must cover this path, not just import/retry:

| Trigger/target | Required persisted purpose and authority |
| --- | --- |
| Initial import or explicit retry, media root | Only a matching `media_weave_attempts` row and exact `media:<source-id>:<position>` trigger grant interpretation authority. Require its open slot, media-read witness and atomic result pointer for every interpretation, including receipt replay. |
| User title clear, media root | Retain `title-clear:<invitation-id>`, but classify it **title-only** from the persisted subject/trigger and absence of an attempt mapping. Its prompt receives eligible descriptor/clarification and an existing eligible initial interpretation if available. Advertise/enforce only conditional `title-fill` and completion: no interpretation, development, connection, application media-open or file parts. Completion needs no interpretation and does not alter attempt state or grant retry. Native bindings retain the agreed trusted-tool policy, not a new sandbox. |
| Capture/import/Evolve follow-up, manual or unknown trigger, media root | Reject admission unless it is one of the two cases above; default-deny execution and replay as well. Ordinary capture excludes this new kind. Evolve follow-up normally targets its newly issued development or contribution, not the old media root. Restoration schedules no work. |
| Ordinary weave of a non-media child; Evolve starting at the media root | Preserve normal behavior: Evolve first records a user contribution and parents developments to that contribution. It may reopen eligible originals, but never issues the source root's initial-interpretation receipt or pointer. |

The purpose check belongs in shared weave admission, context/capability rendering, attachment authorization, operation dispatch/replay and finalization. It is derived from immutable persisted intent plus the attempt mapping, not a caller/model flag or prompt wording. Thus title regeneration remains available before/after a failure or rejected interpretation without becoming an implicit retry or duplicate summary. No new run/agent kind is introduced.

## External artifact ownership and admission

Recommend `THOUGHTLOOM_MEDIA_DIR`, an absolute dedicated directory, defaulting to `<canonical-db-path>.media`. A matching `media_store.store_id` marker prevents accidentally using another library's files. On restore, identity follows the restored database/marker pair, not the old inode. Never initialize a missing marker over an existing populated directory or accept a mismatch. Fresh directories/files use `0700`/`0600`; validate ownership and reject unsafe writable, symlink or hard-linked storage rather than recursively repairing it. Only the daemon needs this directory, not Next.js or OpenCode.

Recommended layout is `objects/<source-id>`, `staging/<random-id>.partial`, and `prepared/<random-id>` for temporary derivations. Names supplied by users are metadata only. Derive every opened path from an internal validated ID/key under an owned directory handle; reject symlinks, nonregular files, hard links, path escapes and unexpected ownership. Use no-follow/exclusive creation and verify file identity, length and digest before serving or preparing an attachment. Do not accept a client filesystem path, `file:` URI, URL, archive or arbitrary storage key. The execution-owner lease remains the single deployed daemon owner; media mutation and cleanup also check its lifetime fence.

### Upload validation and resource safeguards

- Multipart contains exactly one bounded UTF-8 `metadata` part with `{name,clarification?}` and one binary `file` part. Reject unknown/duplicate fields, parts, query parameters and malformed singleton headers. Omitted clarification means default summary; a supplied clarification must be nonblank and retain its exact text. The multipart filename and claimed file MIME do not control identity or dispatch.
- `name` is a display basename, 1–255 UTF-8 bytes: no separators, NUL/control characters, `.` or `..`, absolute/drive path syntax. Never use it as a disk path, executable argument or response-header value. Do not silently normalize conflicting replay metadata.
- Detect actual content, then structurally validate against the allowlisted raster/PDF formats. Signature alone and extension alone are insufficient. Reject empty/unparseable files, invalid or unresolved inspected structures, encrypted/password-protected PDFs, SVG/HTML, archives, executable/polyglot content detected by validation, PDF embedded files and active executable actions. A maintained PDF parser may repair some framing; acceptance requires the resulting inspected structure to pass the same policy. Do not execute PDF JavaScript, resolve external resources or extract embedded files. This is bounded format validation, **not full PDF-conformance certification or a malware-free guarantee**.
- Proposed local defaults: 20 MiB source, 4 KiB metadata, 64 KiB multipart framing, two active receivers; image dimensions at most 16,384 per axis and at most 40 million aggregate decoded pixels across frames; PDF at most 200 pages. These are application resource limits, not claims about provider PDF limits or a model's usable context. Reject rather than silently truncate frames/pages. Validate parsers/decoders in an owned process with explicit memory/output/time bounds; choose and measure those process bounds with the actual dependency before release. No converter/package is installed implicitly.

The implementation candidate is a single validator child with Linux allocation/CPU/core limits plus supervised wall-time and output limits. `RLIMIT_DATA` is an allocation limit, not a universal RSS cap. Isolated compatibility probes support a 1 GiB DATA startup setting for the selected libraries and demonstrate native allocation refusal under a smaller post-load limit; they do not establish a universal native-memory guarantee or power-loss durability. Actual validator integration and hostile-format fixtures still require their own tests.
- Bound the actual stream before parsing, count real bytes independent of `Content-Length`, hash while writing to private staging, and cancel/drain on rejection or disconnect. Reuse the import admission principles, not its whole-file buffering unchanged ([current receiver](../../../src/daemon/markdown-import-routes.ts#L35)). Align Bun, Hono and any future Next/proxy limits, including base64 expansion for native calls. A disk-full or validation failure before admission leaves no canonical source/root/run.

### SQL and filesystem crash consistency

There is no cross-resource atomic transaction. Prefer file-first publication, which can leave a removable orphan rather than a committed source pointing at an unpublished file:

1. Receive and validate into an exclusive staging file outside SQL. Hold bounded in-memory ownership of active staging/object IDs, including handlers admitted immediately before shutdown.
2. Serialize final admission and cleanup eligibility through one daemon-owned gate. Check an existing request key first, comparing exact metadata and actual retained bytes, not only their digest. Identical replay returns its existing receipt without another run. Different input conflicts. There is no content-wide deduplication.
3. For a new key, flush/fsync the original, publish it without replacement into the same-filesystem final location, and fsync affected directories before the SQL commit. No long-running SQL transaction surrounds file I/O or decoding. Revalidate the owned file identity at this boundary.
4. In one immediate SQL transaction create the source/root/title/empty seal and ordinary initial weave plus attempt. Return success only after commit. An ambiguous HTTP result is reconciled by key; neither client disconnect nor model failure removes admitted bytes. A rollback or crash before commit may leave an orphan. A crash after commit leaves the already-published original and durable queued job. Verify SQLite durability settings and real filesystem guarantees rather than infer power-loss guarantees from rename alone.
5. Join upload/validation/preparation lanes before database and execution-lease release, extending the [existing handler/worker drain](../../../src/daemon/runtime.ts#L64). Shutdown is not user Stop. Clean interrupted unadmitted staging best-effort; restart cleanup handles leftovers.

Cleanup scans only recognized entries in those three owned subdirectories, with a finite cursor and a proposed maximum 100 entries per tick plus a 24-hour orphan grace period. Exclude active admissions and recheck SQL references under the same gate immediately before unlinking an orphan. Never follow links or recursively remove unknown entries. Referenced originals are never garbage-collected, including when rejected, failed or apparently duplicate. Retain prepared derivatives while a run can submit or its native outcome is unresolved; remove them only after its local lane joins and no future dispatch needs them. Retained part hashes remain available for terminal history verification. Missing/corrupt referenced originals return visible `original-unavailable`, never metadata deletion, silent recreation or cleanup permission.

## Proposed daemon API

All routes below are user-only bearer-authenticated, reject AI credentials before reading bodies, and use `Cache-Control: private, no-store`, including errors. Existing service roles are not new user accounts. Writes reject query parameters. Idempotency keys use the current import token syntax, 1–128 ASCII letters/digits/`._:-`, but a separate media namespace.

| Method and path | Request | Response |
| --- | --- | --- |
| `POST /imports/media` | Multipart above; required `Idempotency-Key` | `201 {receipt,source,thought,processing}` after durable source admission; exact replay `200` with the same identities/current processing. Agent configuration/connectivity is not required to retain the source. |
| `GET /imports/media/by-key/:requestKey` | No body/query | `200 {receipt}` or `404`. Control-only receipt `{sourceId,thoughtId,createdAt,latestRunId}` reconciles a lost admission response without reupload or hidden content. |
| `GET /imports/media/:sourceId` | Optional existing user `scope`, default normal | `200 {source,thought,processing}` if the source root is visible in that scope; otherwise `404`. This does not invoke an agent. |
| `GET /thoughts/:id/media-source` | Same optional scope | `200 {source:null}` for a visible non-media root, otherwise `{source}` for that root. Missing/invisible thought is `404`. No automatic ancestry walk or descendant access grant. |
| `GET /media-sources/:sourceId/raw` | Optional scope, default normal; rejection inspection requires explicit user history/show-rejected | `200` exact bytes for a visible source root, detected content type, constant safe attachment name by format, `Content-Length`, `nosniff`, private/no-store. No Range/inline PDF renderer API initially. |
| `POST /imports/media/:sourceId/retry` | JSON exactly `{}`, required `Idempotency-Key` | `202 {processing}` for a fresh eligible attempt; `200` for its exact replay. No upload or clarification replacement. |

`source` is `{id,thoughtId,name,mimeType,byteLength,sha256,createdAt,clarification,clarificationAuthor,fileAuthorship:'unverified'}`. It contains no absolute storage path, native identity or credentials. `thought` is the scoped discriminated projection above. `processing` is `{run,interpretationStatus,interpretationThoughtId,retryState,error,agentsConfigured}`. Its bounded `run` is `{id,kind:'weave',status}`; `interpretationStatus` is `pending`, `ready`, `failed`, `interrupted`, or `unavailable`. A confirmed child makes it ready even if later connection work fails; preserve that run failure separately. A rejected child is unavailable in normal projection, not permission to recreate it; return its ID only when visible in the same scope. `retryState` is `not-applicable` for a confirmed initial child, `active` for an open attempt, `reconciling` for pending sealed cleanup, `available` for a cleared eligible predecessor, otherwise `blocked`. Agent configuration remains separate. `error` is null or `{code,retryable}`; unconfigured initial work stays queued with `agentsConfigured:false`, not falsely failed. Upload replay of a later-rejected root returns its control-only receipt with `source`, `thought` and `processing` null, never broader scope or new weaving.

Existing `GET /runs/:id` and `POST /runs/:id/stop` remain the run controls. Source acceptance is independent of interpretation completion. There is no media batch, seal, catalog, overwrite or delete endpoint in this proposal.

Errors use sanitized `{error,code}`: `400 invalid-media-request`; `401 unauthorized`; `403 forbidden`; `404 not-found`; `409 idempotency-conflict`, `attempt-active`, `interpretation-exists`, or `prior-attempt-unsettled`; `413 source-too-large`; `415 unsupported-media-type`; `422 unsupported-source-content`; `500 media-operation-failed`; `503 receiver-busy` with `Retry-After`, `media-store-unavailable`, or `agents-not-configured` for a **fresh retry**. Storage failure after an uncertain commit requires by-key reconciliation, not an assertion that nothing saved. Post-admission interpretation errors live on processing status, not as retroactive upload rejection. Known retry replay, source reads, status and Stop work without current agent configuration; a rejected source cannot become visible through retry replay.

Future browser upload, status, retry and download must use fixed same-origin Next handlers: browser → Next server → authenticated daemon. Next validates Host/Origin, keys, limits and upstream receipts, streams private bytes back with controlled headers, rejects redirects and never gives the browser a daemon URL/token or disk path. Do not extend the existing Markdown-only [web import boundary](../../../apps/web/src/server/import.ts#L88) into a generic proxy. This describes a future consumer contract, not authorization to implement the client now.

## Scoped AI discovery, transport and execution

### Discover and reopen without widening other roles

The media Thought variant makes its eligible descriptor and exact separately attributed clarification discoverable in initial context and full `readThought` results. Search/Export understand that same variant, but gain no binary access. Add `readMediaSource {thoughtId}` only to non-title-only Weaver/Evolve's advertised and enforced capability set; it resolves a media root, not an arbitrary attachment ID/path. Its confirmed result prepares native file parts for the successor prompt rather than putting base64 in JSON capability results or SQLite. Do not use a descriptor read as a binary-read witness.

For the initial media attempt, prepare and attach its original at the first model-bound prompt rather than hope the agent guesses to request it. Ordinary non-title-only Weaver/Evolve discovery advertises reopening explicitly. Evolve already selects its visible evolution path, including an eligible media-root descriptor. To reach a source from a separately discovered interpretation, follow visible immediate-parent/provenance references through scoped reads, never raw ancestor traversal. Title-only jobs receive no original automatically or on demand. Native tool output is not a daemon-confirmed media witness.

Preparation must be two-phase: scoped metadata selection/claim checking, then asynchronous file verification/conversion outside SQL, then a short guarded transaction committing the exact text, part manifest and exposures together. Media successor advancement creates its new step, inserts parts while its input is null, and seals the exact input atomically with the predecessor's confirmed result. This extends the currently synchronous [`prepareInitial`](../../../src/storage/run-worker.ts#L20) and text-only [`advance`](../../../src/storage/run-protocol.ts#L76) paths; their renderers must not acquire filesystem/network work inside a transaction.

Check source-root eligibility and the run claim before/after asynchronous open, preparation, native calls and receipt delivery; record the source thought in `run_context` atomically with exposed metadata/parts/results. A rejected source hides its descriptor, name and bytes even through an active child. Rejecting only an interpretation does not reject the independent source. Shared replies retain their existing stricter AI association rule. Replay revalidates eligibility before returning cached metadata or reconstructing files. Add immediate media-dependent run fencing to the rejection command transaction, including queued media-attempt subjects not yet prepared, so reject-then-restore cannot revive an exposed generation; restore does not resume old work. The existing [transactional rejection hook](../../../src/storage/rejection.ts#L87) currently eagerly fences search, while ordinary context guards run at later boundaries. This new media-dependent invalidation is required, not already implemented.

Already-sent context cannot be withdrawn. Retained originals and permissive native tools are not a sandbox: operator tools that independently reach storage can bypass application scopes. Keep that accepted limitation explicit. Search, Export and Markdown segmentation receive no media-open capability or native/MCP permission expansion; they can continue reading eligible recorded interpretations. Never route Markdown document IDs through the media service or globally expose retained source artifacts.

### Portable native input and exact recovery

Use the maintained `session.prompt` file input, not the experimental decisions API. Recommend an **in-band** transport: construct deterministic `data:<mime>;base64,...` URIs with `source:{type:'inline'}` and constant safe names from verified bytes. This avoids assuming that the operator service shares the daemon's filesystem or can fetch a loopback URL. It does **not** prove the configured service accepts that URI representation; establishing SDK/service normalization and delivery is an implementation compatibility gate. Do not silently fall back to `file://`, shared mounts, public/signed URLs, bearer-token URLs or exposing a daemon raw route to a remote service. Supporting another topology would need an explicit transport/configuration decision.

Extend `PersistedPrompt`, the injected facade and real SDK projection to carry an ordered immutable attachment manifest alongside existing exact text. Extend inbox, native user history, submission authorization, observation and cancellation checks to compare decoded bytes by length/SHA-256, MIME, constant name, inline source and exact order against the persisted parts. Hash SDK-decoded attachments at the facade boundary and retain only fingerprints in accumulated native-history projections, not all historical base64 payloads. The SDK's individual response still needs a measured transport/memory bound. Reconstruct the identical URI bytes from the retained original or prepared derivative on pre-dispatch retry. Reject missing/extra/reordered/changed parts, foreign URI sources, agents/skills/metadata and untracked native context. Do not simply remove the current `files.length` safety checks. Existing text-only and restricted runs retain empty attachment manifests and their current checks.

The selected configured standard model/variant remains bound through existing bindings. An advertised image/PDF modality is only advisory; check capabilities actually needed and classify explicit input rejection safely. Neither SDK acceptance, documented image/PDF support nor a newer service version guarantees the chosen provider, image fidelity, PDF page handling or request/context limits. Do not silently select another model. Service unavailability before dispatch preserves queued/prepared work; after durable submission intent, lost acknowledgement or incomplete history remains observation-only with the same session/prompt and parts.

Temporary extraction/conversion is permitted through an injected preparer, not additional persisted thoughts or a new agent kind. Originals never change. A derived file is private `prepared/` scratch with a persisted MIME/length/digest and recipe recording converter/version/options, source coverage and limitations. Publish/fsync it before committing its exact prompt parts, using the same orphan discipline. No converter is assumed installed. Start with direct original input; add only a validated representation the configured model/service can actually consume, such as PDF page images when image input is supported. Text extraction needs its own verified transport representation; do not assume a text-only model reads an arbitrary file attachment. If no verified path exists, expose `conversion-unavailable` or `unsupported-model-input` and preserve the original for retry. Never silently drop pages/images or substitute a misleading complete summary for partial extraction. Disclose extraction/OCR/visual limitations in the interpretation and Full reply. Input files and extracted text are untrusted data, not application/tool instructions.

### Initial result, failure and deliberate retry

Reuse the ordinary worker/supervisor lane, weave scheduling identity, fenced writes and Full reply finalizer. Add the persisted media-purpose policy, not another generic import worker or run kind. An **interpretation attempt**, unlike title-only or ordinary no-findings weaving, requires a source-grounded child: completion without one records `interpretation-missing` and a failed local run while retaining a safe completed Full reply explaining limitations. A valid child can remain saved if later work fails. Further weaving does not recursively enqueue another media import.

The current [`correlateHistory()`](../../../src/agent/history.ts#L108) deliberately treats unsuccessful or empty final output as uncertain. It cannot support visible terminal media failures unchanged. Add an owned media-attempt terminal classifier that retains positive terminal facts for its exact text/file history, including settled permissive tool turns, and distinguishes a native failure from an unknown history. Reuse shared history ownership checks, not Markdown's deny-only single-turn terminal assumptions. No error message, timeout, idle absence or empty history alone establishes that a potentially paid attempt failed.

Fresh retry requires an active source, configured agents, no confirmed initial interpretation, no open attempt, and `cleanup_state='settled'` with matching retained retry evidence for its immediate predecessor. Ordinary cancellation's current empty-inbox/inactive `settled` result ([adapter:385-406](../../../src/agent/opencode-adapter.ts#L385)) is insufficient. Unknown outcome, pending cleanup, conflicting native context or missing evidence returns `409 prior-attempt-unsettled`; it never licenses a speculative replacement. The handler performs no native call and never attempts to observe with a terminated claim.

Retry creates a new ordinary weave/attempt with a new daemon identity and next position, while preserving original bytes, clarification, failed run and receipts. Same-key replay returns that attempt even if configuration later disappears; new keys race through the one-open-slot constraint. A confirmed initial child permanently ends this retry path, even if that child is subsequently rejected. Use deliberate Evolve for a new interpretation, not retry that recreates rejected output. A rejected-context run can never replay or publish late work after restoration.

### Sealed attempt reconciliation after termination

Current [`observe()`](../../../src/agent/opencode-adapter.ts#L226) requires an active claim, which [`active()`](../../../src/storage/run-aggregate.ts#L55) rejects after Stop/failure. Introduce a narrow `reconcileMediaAttempt(identity,authorize)` extension of the cancellation seam, **independent of active execution and source eligibility**, with only `pending`, `ownership-conflict`, or typed `settled` evidence as outcomes. This is new required authority, not reuse of ordinary `observe()` or its `pending|settled` cancellation result.

1. **Seal when fencing.** In the same immediate transaction as Stop, local failure or rejection, increment/fence the run generation, close the attempt slot, set its failure code and `cleanup_state='pending'`, and write `cleanup_identity_json`. The strict version-1 seal contains source/run IDs, fenced generation, the saved binding or null, and the complete ordered step manifest: position, prompt ID, exact text hash (null only if never prepared), ordered attachment fingerprints/names/inline-source policy, and `authorization:'never-authorized'|'authorized'|'unknown'`. Authorization is journal state recorded **before** dispatch, not an ACK or binding inference. Block further preparation, step insertion, dispatch and knowledge writes for that attempt. Unknown facts cannot yield clearance. Repeated Stop reuses the same seal; restoration cannot modify it.
2. **Join and schedule.** The daemon-owned worker appends reconciliation only after the actual execution promise has joined, using the existing [registered cleanup-tail pattern](../../../src/agent/worker.ts#L105). Never self-join from failure handling or drop a held flight. The bounded supervisor scans terminal attempts with pending seals, even when ordinary `cancellation_state` was previously marked settled. After restart, the held registered execution lease and terminal seal authorize this cleanup lane, not a reclaimed execution claim. Without agent configuration, settle locally provable never-submitted seals only; native-dependent seals remain pending. Rejection does not prevent metadata-only cleanup.
3. **Reconcile without execution.** A repository authorization callback checks the current lease, exact immutable seal/binding, fenced generation, terminal run and closed slot before/after every native call. Permit only owned-session lookup, history/inbox/active reads and cancellation/interrupt operations. No session creation, prompt, source-file open, attachment retransmission, conversion, application capability, model-result finalization or late publication is authorized. Historical native bodies may be read transiently to hash/validate them; discard prose and file data without exposing them to AI, user replies or logs. Verify exact owned text/file history and settled tool turns, and collect positive terminal facts for **every authorized prompt**, not just the latest. Missing sessions, empty history, outage or cancel ACK alone remain pending; foreign/conflicting context becomes ownership-conflict without interrupting a foreign session.
4. **Retain clearance atomically.** After the final native boundary, recheck the unchanged seal/terminal generation and joined-lane authority in one immediate transaction. Write once either `{version:1,sealSha256,kind:'never-submitted'}` from a complete never-authorized journal, or `{version:1,sealSha256,kind:'terminal',prompts:[{promptId,userMessageId,idleMessageId,idleOutcome}]}` covering every authorized prompt with matched `succeeded|failed|interrupted` terminal evidence. Set `cleanup_state='settled'` and ordinary cancellation settlement together. No further native call is allowed under that seal. Do not change run outcome/generation, parts' execution witnesses, receipts, interpretations or Full replies. Pending polls publish nothing. Retry admission revalidates this exact seal/evidence in its own slot-admission transaction; a restored source can start a new explicit attempt but cannot revive the old one.

Successful attempts with a confirmed child need no retry seal. Terminal failed/interrupted attempts retain pending seals even if they already saved a child; cleanup can finish without enabling another initial interpretation. An unacknowledged prompt cancelled before any positive admission/terminal evidence may remain unresolved indefinitely. That is an explicit conservative retry limitation, not grounds to replay paid work. Existing ordinary/Search/Markdown cleanup contracts are otherwise unchanged.

## Operations, validation and handoff

The existing [deployment backup procedure](../../../docs/production-deployment.md#5-back-up-upgrade-and-recover) covers the stopped database set only. Extend it at implementation time to a single stopped snapshot containing the SQLite set, matching media marker, originals and any prepared files needed by unresolved runs. Protect backups as sensitive content. Restore database and media together with the matching release/configuration; verify marker, reference inventory, lengths/digests and ownership before enabling media dispatch or cleanup. Preserve broken/mismatched backups for diagnosis. Do not start workers against only half a restore, silently recreate a missing populated store, or advertise SQLite-only export as a full backup. No live cross-filesystem snapshot guarantee or native/provider-history erasure is implied.

Media configuration is separate from Markdown's 1 MiB setting: propose `THOUGHTLOOM_MEDIA_MAX_BYTES=20971520` and the directory setting above. Validate bounds without echoing values or paths. Verify/create the owned store locally at startup, but retain lazy operator-service attachment. No agent configuration means successful retention and queued interpretation, not a service call or substitute model. Keep existing daemon lifetime ownership, bounded shared scheduling and shutdown joins. Prepared media payload totals/conversion output need independent finite technical bounds that account for base64 and decoded history; source-byte limits alone do not bound memory. Native/operator logging and provider retention remain separate trust boundaries.

## Recommended decision

Recommend a narrowly typed `media-original` root with null text and separately attributed exact clarification, file-first private retention, purpose-guarded ordinary weaving and sealed metadata-only retry reconciliation. Start with verified direct in-band image/PDF input; permit bounded temporary conversion only when validated. Honest source attribution costs a tested enum/nullability/FK migration; retained originals cost paired backups. Neither requires a global attachment system.

The user approved the **`media-original` source-root representation and its null-text/descriptor projections**. Do not implement the earlier invented user-text fallback. The settled image/PDF, retention, interpretation and trust boundaries are unchanged. Implementation and any client/visual or live compatibility work require a separately commissioned scope.
